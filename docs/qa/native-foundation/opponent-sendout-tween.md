# Native opponent send-out visual tween

The existing public tween seam was never invoked by a native send-out, so a
presentation provider could not begin its opponent throw/return actor. Offer
that seam from the actual opponent ball constructor and drive it from the
same native update owner. No private actor/controller body is included.

The35-unit presentation protocol has16 opening-delay units,12 emergence units
and7 trainer-exit units. Map those coordinates to the actual imported delay/
fade durations; they are not advertised as cartridge frame counts. A provider
may extend the visual interval. Each mapped step consumes the existing native
ball update at most once per native tick; sounds/reveal remain in that body.
The actual native wait is admitted once, retained through a visual return and,
when necessary, the remaining native shiny tail. Default and delegating paths
keep the entire native frame/queue/wait/position/HP/PP/sound trace identical.

Only the genuine native opponent intro is admitted. Detached task observations
grant no timing authority. Callbacks are usable only inside their current
native visual phase/coroutine ancestry; later callers and retired suspended
children cannot spend a saved step. Hook/owner removal, reset and callback
errors discard source callbacks and resume the remaining native ball without
replaying its queue row. Cohort replacement revokes the old observation. Five
native owners collect even when a task/callback is retained; the existing last
completed battle snapshot remains scalar/read-only by design.
