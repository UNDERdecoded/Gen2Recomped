# Native player throw and opening phases

The native battle now offers the existing presentation callback a player windup/flight phase (57 public units: 32 windup and 25 flight) and a separate emergence phase (12 public units mapped to the actual native fade). The actual native ball, battler, queue and simulation clock remain authoritative. A source decorator may hold its visual return; default and delegating providers retain exactly the native trace.

An opening notification borrows the actual native release transition after its opening sound has been spent. It does not manufacture a second ball or opening effect. The scoped original callback rejects another actor, nonfinite positions, replay and callbacks retained beyond their native frame/cohort. This lets an unchanged presentation retire its throw pose at the actual opening.

Validation on the merged fork main `6ab3709e`, owned implementation `263f7585`: 244 frozen CPU groups passed. The player fixture checks 2,110 assertions across five editions, including exact default/delegating traces, decorated windup/flight/emergence, cancellation, error fallback and stale phase retirement. The opening fixture checks 345 assertions, including sound ordering, actor/frame identity, pure coordinate borrowing and throw-to-return handoff. The prior implementation fails 40 of the player fixture's first 70 assertions; its native controllers were not overlaid.

The older public integration is checked separately over its original native controllers. This change does not qualify all switch/capture presentations or sustained field rendering performance. The current water-view investigation separately reproduced a roughly five-second frame and a missing general door metadata query in Third Person; those issues remain outside this battle change. Real unchanged-consumer player return remains a visual follow-up; CPU phase qualification is not visual acceptance.

Only owned disposable profiles were used. No player saves or private presentation source were changed. Storage helpers enforced at least 20 GiB free (above the user's 8 GiB requirement).
