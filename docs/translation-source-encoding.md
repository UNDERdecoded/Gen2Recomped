# Translation generation across source and manifest formats

The full `modkit translation` command stopped while reading an existing
non-UTF-8 byte in a `MoveEffects.lua` comment. The comment is not a catalog
key, but decoding the entire file strictly prevented every translation mod
from being generated or refreshed.

The harvester now reads source with reversible surrogate escapes. Bytes
outside harvested string literals remain untouched. Every harvested literal
must still encode as UTF-8; an invalid literal produces a file/line diagnostic
and a failing CLI exit before the mod output directory is created. No source
encoding is guessed, and the game files are not rewritten.

The generator also supplies the metadata slots used by the parameterized
shared manifest template. Without those substitutions, the composed fork
wrote literal `{{api}}`, `{{games_line}}` and `{{engine_range_line}}` tokens
and produced invalid JSON. Both template layouts now retain the translation
mod's API-2 declaration and existing engine-version range.

Validation:

- **7/7** unit tests pass, including the actual repository scan, unchanged
  legacy source bytes, UTF-8 source keys, quote normalization, invalid-key
  diagnostics, CLI error handling and both manifest layouts. Six tests fail or error with the
  unchanged parent implementation.
- A real CLI run scans the complete source tree and harvests **1,442 engine
  keys**, generates a mod, then refreshes it while preserving an edited
  UTF-8 translation. The parent CLI instead raises `UnicodeDecodeError`.
- Normal validation passes and the generated, refreshed mod loads through
  the real SDK with its generated bytes in a memory filesystem. Its preserved
  translation is observable through the public `Strings` runtime.
- The composed fork passes **20/20 Python tool tests**. Its real, parameterized
  manifest template generates valid JSON, and the complete **1,498-key**
  catalog workflow passes generation, refresh, normal validation and SDK
  loading with the preserved UTF-8 translation.
- The ROM-free fixture cannot supply an imported font dump. Strict
  validation still fails with the existing **MK305** warning; that result is
  retained and is not counted as passing.
- The seven unit tests are included in the existing CI lint job. Actionlint
  and `git diff --check` pass locally.

Reproduce the unit tests and fixture-based generation:

```sh
python3 -m unittest discover -s tests/tools -p test_translation_source_encoding.py -v
LUA=luajit python3 tools/modkit.py translation catalog_probe --base fixture --dest /your/test/output
LUA=luajit python3 tools/modkit.py translation catalog_probe --base fixture --dest /your/test/output --refresh
```

The [verification receipt](qa/translation-source-encoding.json) pins the
qualified tool/test bytes and local evidence hashes. Dataset names and
dialogue in the CLI probe come from the committed three-species fixture;
no ROM, normal game save or graphics/audio device is used. Production Lua
sources and native engine contracts are unchanged.
